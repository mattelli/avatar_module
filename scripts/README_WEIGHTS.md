# Weight conversion pipeline (Plan 5, task 2)

Converts the Wav2Lip + ExpNet PyTorch checkpoints into Burn-importable
records (`.bpk` Burnpack files) that the `wav2lip` and `expnet` crates load
at runtime.

## Model sources

| Model | Checkpoint | Source | Size |
|---|---|---|---|
| Wav2Lip GAN generator | `wav2lip_gan.pth` | https://huggingface.co/Nekochu/Wav2Lip | 435 MB |
| ExpNet (SadTalker) | `auido2exp_00300-model.pth` | https://github.com/OpenTalker/SadTalker/releases/tag/v0.0.2 | 34 MB |

Both are downloaded into `.res/` (gitignored).

## Pipeline

```
wav2lip_gan.pth ──┐
                  ├─▶ convert_weights.py ──▶ wav2lip_gan.onnx / expnet.onnx
auido2exp...pth ──┘        (PyTorch → ONNX, opset 17)
                              │
                              ▼
                    verify_onnx.py  (ONNX vs PyTorch round-trip, < 1e-3)
                              │
                              ▼
                    onnx2burn (burn-onnx 0.22) ──▶ .res/models/<name>.bpk
                              │
                              ▼
                    CHECKSUMS.txt (SHA-256 of every artifact)
```

Run the whole thing on Windows:

```powershell
powershell -ExecutionPolicy Bypass -File scripts/convert_weights.ps1
```

## Python environment

Uses `scripts/.venv-avatar` (torch CPU + numpy). Install the ONNX tooling:

```powershell
scripts\.venv-avatar\Scripts\pip install onnx onnxscript onnxruntime
```

`onnx2burn` CLI:

```powershell
cargo install burn-onnx --version 0.22.0 --locked
```

## Notes

- **BatchNorm folding**: torch's ONNX exporter folds BatchNorm into the
  preceding conv weights, so the exported graphs contain only
  `Conv/ConvTranspose/Relu/Add/Concat/Sigmoid/Gemm/Reshape` — all ops
  burn-onnx supports. The round-trip check tolerates the resulting float32
  error (< 1e-3).
- **`ref` input renamed to `ref_coeff`**: the ExpNet input was named `ref`,
  which is a Rust reserved keyword; burn-onnx would generate invalid Rust
  (`let ... [.., ref, ..]`). The ONNX export renames it.
- **ExpNet reshape**: `.view(x.size(0), -1)` is replaced with a static
  `reshape(-1, 512)` so the ONNX graph avoids a Shape-slice node that
  burn-onnx's formatter cannot handle.
- **Windows DX12**: see the workspace `Cargo.toml` `[patch.crates-io]`
  note for the `gpu-allocator`/`windows` version fix.

## Checksums (`.res/models/CHECKSUMS.txt`)

Generated by the pipeline; verify with:

```powershell
Get-FileHash .res\wav2lip_gan.pth -Algorithm SHA256
Get-FileHash .res\expnet.onnx -Algorithm SHA256
```
